# ADR-007: Human Clinical Oversight & AI Decision-Support Boundaries

* **Status:** Accepted
* **Date:** 2026-08-11
* **Deciders:** Lead Software Architect, Healthcare Compliance Lead

## Context
Deploying Artificial Intelligence in emergency healthcare introduces clinical safety risks if AI predictions are treated as autonomous medical authorities.

## Decision
All AI and ML outputs generated by MyHealthChain (including XGBoost ESI classifications, Gemini command reports, and health risk categorizations) are strictly designated as **Clinical Decision Support (CDS)**. 

Key Operational Boundaries:
1. **Decision Support Labeling:** Every AI response returned via API or displayed in the UI contains explicit labels: `AI-Assisted Assessment — Requires Clinician Confirmation`.
2. **Authoritative Clinician Control:** Physicians and triage nurses retain full manual override authority to upgrade or downgrade patient ESI priority levels or modify prescription orders.
3. **Graceful Fallbacks:** If an AI model or external API fails, the system transitions to deterministic clinical rule-sets and notifies the operator rather than fabricating answers.

## Consequences
* **Positives:** Maintains strict compliance with medical ethics and software safety standards; prevents autonomous medical error propagation.
* **Negatives:** Requires explicit UI badges and manual confirmation steps for clinical actions.
